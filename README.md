## ⚙️ Как выбрать рабочий сервер

TCP ping и реальная работоспособность VPN — не одно и то же.

Открытый TCP-порт ещё не означает, что через сервер получится нормально пользоваться интернетом.

Поэтому предпочтительно использовать функцию:

**Real Delay / Реальная задержка**

И затем:

1. обновить подписку;
2. запустить реальную проверку;
3. отсортировать серверы по задержке;
4. попробовать несколько лучших вариантов.

<details>
<summary><strong>Почему конфиг работал вчера, а сегодня нет?</strong></summary>

Публичный сервер мог быть перегружен, отключён, заблокирован или просто перестал отвечать.

<details>
<summary><strong>Почему verified-конфиг не подключается именно у меня?</strong></summary>

Проверка выполняется в определённый момент времени. Условия у вашего оператора, сети и устройства могут отличаться.

Попробуйте:
- обновить подписку;
- другой сервер;
- другой клиент;
- `ru_configs.txt` для сценариев с белыми списками.
</details>

<details>
<summary><strong>Почему нужно использовать Real Delay, а не TCP ping?</strong></summary>

TCP ping проверяет сетевую доступность порта. Реальная задержка проверяет возможность фактического VPN-соединения через клиент.

Для выбора рабочего сервера ориентируйтесь прежде всего на реальный тест.
</details>

<details>
<summary><strong>Что делать, если GitHub не открывается?</strong></summary>

Используйте зеркало файла, например:


или:

```text
https://cdn.jsdelivr.net/gh/aviamastersgh/vpn-free-russia@main/verified_configs.txt
```

Зеркала не являются отдельным источником конфигураций: они доставляют содержимое соответствующего файла.
</details>

<details>
<summary><strong>Можно ли использовать несколько устройств?</strong></summary>

Это зависит от VPN-клиента, конкретного конфига и ограничений сервера.

Для публичных конфигов нельзя гарантировать одинаковое поведение на всех устройствах.
</details>
